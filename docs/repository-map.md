# Repository structure

Use [the final report](final-project-report.md) for the submission narrative and
[the viva command menu](viva-command-menu.md) to choose a live demonstration.

| Directory | Purpose |
| --- | --- |
| `backend-a/`, `backend-b/` | Active Python application sources |
| `phase2/` | Current inventory, managed setup, backend controls, diagnostics, captures, orchestration and evidence packaging |
| `tests/` | Small DNS, connectivity, backend, cache and distribution probes |
| `dns/`, `edge/` | Historical Phase 1 public configuration references; not installed live configuration |
| `tls/` | Public certificate configuration and TLS setup/verification notes |
| `docs/` | Architecture, request flow, final report sources, demo guides and historical notes |
| `evidence/` | Immutable observations, original failures, successful repeats, PCAPs and snapshot manifests |
| `output/pdf/` | Final report PDF, shareable viva guide and artifact manifest |
| `.runtime/` | Ignored per-Mac live files: nginx configuration, certificates, keys, PIDs and logs; never delete during the demo |

The live DNS configurations are root-owned under `/private/var/db/cn-project`
(Kavya) and `/private/var/db/cn-project-backup` (Priyanshu). Both client resolver
files are `/etc/resolver/cn-project.test`. They are not updated by moving a repo
file or editing an old example. The runtime nginx configuration is generated by
`phase2/render.sh`, but healthy services do not need rerendering or restarting
for this repository cleanup.

## Current entry points

- Start/stop/status backends: `phase2/services.py`.
- Read-only diagnosis: `phase2/diagnose.sh`.
- Read-only saved-packet checks: `phase2/check-capture.py` (TShark required).
- Optional visible Certificate capture: `phase2/capture-tls12.py` on Kavya.
- Manual demo: `docs/viva-command-menu.md`.
- Controlled acceptance suite from Kavya: `phase2/final-tests.py`.
- Additional coordinated failures from Kavya: `phase2/phase1-failures.py`.
- Restore and verify from Kavya: `phase2/recover-live.py`.
- New network deployment only: the installers and `phase2/MAC3-SETUP.md`.
  Existing helpers refuse overwriting; do not reinstall during a live demo.

## Removed obsolete files

The cleanup removes the old root scaffold, certificate repair/replacement,
PID-reset and original failure-test scripts, along with the obsolete
`phase2/admin-setup.sh` shortcut. Those tools could overwrite source, replace a
CA, use old addresses, restart retired DNS, or overwrite historical evidence.
Their current replacements are listed above. Unused generated `server.csr`
and `ca.srl` artifacts were removed; public `tls/generated/server.ext` remains
because the original configuration bundle references it.

For historical inspection, commit `dab9501` contains the pre-cleanup tree.
For example, `git show dab9501:setup_repo.sh` displays the old scaffold without
executing it. Old documentation warnings about that filename refer to Git
history, not to a current setup command.

Every existing evidence/PDF file and local runtime file was preserved. Historical
manifests record source snapshots from their original collection commits; they
are not rewritten to make old code snapshots describe the current tree.
